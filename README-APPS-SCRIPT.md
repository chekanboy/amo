# Бэкенд Apps Script — настройка и деплой

Бэкенд дашборда — файл [`amocrm_final_v2.gs`](amocrm_final_v2.gs), развёрнутый как веб-приложение
Google Apps Script. Фронт обращается к нему через `fetch` (URL вводится в дашборде кнопкой ⚙).

## Токены хранятся вне кода

В коде **нет** ни одного токена: репозиторий публичный, и ключи в файле утекли бы в открытый доступ.
Значения лежат в **Script Properties** самого проекта Apps Script. Код читает их так:

```js
const AMO_TOKEN = PROPS_.getProperty('AMO_TOKEN') || '';
```

Нужны 4 свойства:

| Свойство | Что это |
|---|---|
| `AMO_TOKEN` | долгосрочный токен AmoCRM (JWT) |
| `METRIKA_TOKEN` | токен Яндекс.Метрики |
| `DIRECT_TOKEN` | токен Яндекс.Директа |
| `CT_TOKEN` | `clientApiId` Calltouch |

Если свойство не задано, дашборд покажет понятную ошибку с именами недостающих свойств,
а не пустые нули.

## Как прописать свойства (делается один раз, вручную)

1. Открыть [script.google.com](https://script.google.com) и зайти в проект дашборда.
2. В левом меню нажать **⚙ Настройки проекта** (Project Settings).
3. Пролистать вниз до раздела **Свойства скрипта** (Script Properties).
4. Нажать **Изменить свойства скрипта** → **Добавить свойство скрипта**.
5. Добавить 4 пары «имя → значение» из таблицы выше. Имена писать **точно** как в таблице,
   заглавными, без пробелов. Значения — взять из локального файла `TOKENS.local.md`
   (он лежит рядом с проектом и намеренно не попадает в git).
6. Нажать **Сохранить свойства скрипта**.

## Как обновить код и передеплоить

1. В редакторе Apps Script выделить всё содержимое файла и заменить на актуальный
   `amocrm_final_v2.gs` из репозитория. Сохранить (Ctrl+S).
2. **Развернуть** → **Управление развёртываниями**.
3. У существующего развёртывания нажать ✏️ **Изменить**.
4. В поле **Версия** выбрать **Новая версия** → **Развернуть**.

> Важно: именно **изменить существующее** развёртывание, а не создавать новое — тогда URL
> веб-приложения не поменяется и в дашборде ничего перенастраивать не придётся.
> Если создать новое развёртывание, URL будет другой и его нужно заново ввести в дашборде через ⚙.

## Проверка, что всё поднялось

Открыть дашборд и обновить данные (↻). Признаки успеха:

- метрики заполнились, вверху появилась дата обновления;
- в карточке **«Ждут поставку»** есть число, цифра кликабельна;
- ошибок вида «В Apps Script не заданы свойства скрипта: …» нет.

Если появилась такая ошибка — значит какое-то свойство не сохранилось: вернуться к шагу 5 выше
и проверить написание имени.

## После настройки

Файл `TOKENS.local.md` можно удалить — значения останутся в Script Properties.
Резервная копия старого кода с токенами лежит в `amocrm_final_v2.gs.tokens.bak`
(тоже вне git). Если она больше не нужна — удалить, чтобы токены не валялись на диске.

## Ежедневный отчёт в Google Таблицу

Отдельная от дашборда фича: раз в сутки `generateDailyReport()` дописывает по одной
строке в 4 листа Google Таблицы («Общее», «По городам», «По сайтам», «По источникам») —
живой журнал для CEO. Источник данных — тот же `buildAmoData()`, что и у дашборда.

### Настройка (один раз)

1. Создать **новую отдельную** Google Таблицу (не смешивать со звонками МегаФона) —
   можно просто открыть [sheets.new](https://sheets.new).
2. Скопировать ID таблицы из адресной строки: `.../spreadsheets/d/`**`ЭТОТ_ID`**`/edit`.
3. В Apps Script → ⚙ Настройки проекта → Свойства скрипта → добавить `REPORT_SHEET_ID`
   со значением этого ID (пятое свойство, помимо 4 токенов).
4. Проверить **часовой пояс проекта** (Настройки проекта → Часовой пояс). Если он не
   `Europe/Moscow` (например, у заказчика оказался `Asia/Bangkok`) — либо сменить его на
   `Europe/Moscow` (рекомендуется, тогда шаг 5 без пересчёта), либо учитывать смещение
   при выборе часа в `installDailyTrigger()`. Сами данные отчёта считаются в МСК всегда,
   независимо от часового пояса проекта — влияет только время СРАБАТЫВАНИЯ триггера.
5. В редакторе Apps Script выбрать функцию `testDailyReport` в выпадающем списке сверху →
   **Выполнить** (▶). Проверить, что в таблице появились строки за вчера и числа похожи
   на правду. Запустить ещё раз — строки должны обновиться на месте, а не задвоиться.
6. Выбрать функцию `installDailyTrigger` → **Выполнить** (▶) — один раз, ставит ежедневный
   триггер. Проверить в Apps Script → Триггеры (часы слева), что он появился и указывает
   на нужное время.

### Идемпотентность

Строка ищется по дате в столбце A — если такая уже есть, перезаписывается, а не дублируется.
Можно спокойно перезапускать `generateDailyReport`/`testDailyReport` вручную сколько угодно
раз за один день, лишний раз ничего не сломает.
